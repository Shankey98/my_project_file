1. 이 폴더의 `Start.cmd`를 실행합니다. Node.js 22 이상이 필요하며, 현재 PC의 Codex 번들 Node.js도 자동 탐색합니다.
2. 브라우저에서 `http://127.0.0.1:47831` 화면이 열립니다.
3. 종료하려면 `Stop.cmd`를 실행합니다. 창을 닫는 것만으로 백그라운드 앱이 종료되지는 않습니다.

명령줄에서는 `node server.mjs`로 실행하고 Ctrl+C로 종료할 수도 있습니다. `Start.cmd`는 PC 재부팅 후 자동 실행을 등록하지 않습니다.

- 여행 수정, 복사, 삭제, 감시 요청 저장/해제, 한국 시각 기준 종료 상태 확인.
- 기존 일반실 결제 상태, 전원 확보 조건, 인접 좌석 선호, 메모 저장.
- JSON 백업 저장·가져오기. 가져온 여행은 일시정지 상태로 추가됩니다.
- PC 연결 끊김 표시와 활동 기록. 데이터는 이 폴더의 `.local`에 저장됩니다.
- PWA 홈 화면 설치용 manifest/service worker와 자체 Web Push 구독·암호화·전송 기능.
- localhost 세션, HTTPS 기기 연결 코드(10분·1회용), 원격 세션, API 요청 출처 검증.
- 기존 Chrome 연결 모듈과 전용 1회용 코드, 날짜·구간·열차 일치 확인, 오래된 결과 제외, Chrome 연결 해제. 확장프로그램 실제 실행 검증은 설치 후 필요합니다.

## 미완료이며 실제로 사용할 수 없는 기능

- 코레일 직접 API 로그인·좌석 조회, 자동 예약 확보, 예약 상태·결제 기한 실시간 조회.
- Chrome 확장 설치 후 실제 결과 읽기·1분 새로고침·PC 알림 수신 검증. UI를 통한 1회 조회 성공과 별개입니다.
- 인접 좌석 조건의 실제 적용. 일부 인원 좌석은 자동 예약 대신 직접 확인하는 방식으로 설계했습니다.
- 휴대폰 외부 접속 및 자체 푸시 실기기 수신 검증. 아이폰과 안드로이드에서 각각 검증해야 합니다.

`감시 요청 저장`만으로는 코레일에 접속하지 않습니다. Chrome 확장을 연결하고 해당 여행의 조회 결과 탭을 열어 두어야 합니다. 확인 결과가 없거나 오래됐으면 감시 중으로 표시하지 않습니다. 서버에는 실제 코레일 API 주소, 회원 비밀번호 저장, 자동 결제·자동 취소 코드가 없습니다.

`lib/reservations.mjs`는 테스트용 공급자를 사용하는 예약 처리 규칙입니다. 실제 서버의 예약 실행에 연결되어 있지 않습니다. 예약 시도 전에 불확실 상태를 저장하고, 결과가 불명확하면 재시도를 중단하며, 전원 인원·특실·열차번호·결제기한을 확인하는 규칙을 테스트합니다. 실제 좌석 확보나 코레일 연결이 검증됐다는 뜻은 아닙니다.

## 자체 푸시

PC의 localhost에서는 지원 브라우저로 알림을 등록할 수 있습니다. 알림 화면에서 연락용 이메일을 저장하고 기기를 등록한 뒤 테스트를 실행합니다. 이메일은 표준 Web Push의 발신자 연락처로 브라우저 푸시 서비스에 전달됩니다. 이메일 알림을 보내는 기능은 아닙니다.

휴대폰은 **해당 휴대폰에서 신뢰하는 HTTPS**로 앱을 열어야 합니다. 아이폰은 iOS 16.4 이상에서 Safari의 홈 화면 추가 후 알림을 허용해야 합니다. 알림 전송 성공은 푸시 서비스의 접수 성공이며 실제 기기 수신을 보장하지 않습니다. 현재 기기 등록이 없어 실전송/실수신 검증은 하지 않았습니다.

Web Push 통신은 Apple/Google/Mozilla/Microsoft의 푸시 중계를 사용합니다. 별도의 상시 감시 서버는 필요하지 않지만 이 중계 인프라는 사용합니다. PC가 꺼지거나 절전 상태이면 새 확인·전송 작업은 수행되지 않습니다.

## 기존 NordVPN 재사용과 HTTPS

PC에 NordVPN 설치와 프로세스 실행이 확인되었습니다. 이름이 일치하는 Meshnet IPv4 인터페이스는 초기 확인에서 발견하지 못했습니다. 이는 Meshnet이 꺼져 있다는 확정 진단은 아닙니다. 휴대폰 연결, Meshnet 권한, 인증서 설치, 방화벽 설정은 변경하지 않았습니다.

Meshnet은 PC 접근 경로를 제공하지만 브라우저가 요구하는 HTTPS 인증서를 자동 제공하지 않습니다. 개인 도메인의 유효한 인증서 또는 본인 휴대폰에서 명시적으로 신뢰한 개인 인증서가 추가로 필요합니다. 인증서 경고 무시를 전제로 구성하지 않습니다.

원격 접속 준비가 된 뒤에만 다음 환경 변수를 설정해 `node server.mjs`를 실행합니다. Node는 지정한 PC 인터페이스 IP와 localhost 관리 화면을 함께 엽니다. `Start.cmd`는 기본 localhost 실행용입니다.

```powershell
$env:KTX_HOST = '<이 PC의 Meshnet IP>'
$env:KTX_PUBLIC_ORIGIN = 'https://<인증서와 일치하는 주소>:47831'
$env:KTX_TLS_CERT = '<인증서 PEM 전체 경로>'
$env:KTX_TLS_KEY = '<개인키 PEM 전체 경로>'
node server.mjs
```

localhost 관리 화면의 `기기 연결`에서 1회용 코드를 만들고 휴대폰에서 HTTPS 주소를 열어 코드를 입력합니다. 외부 HTTP 공개와 모든 인터페이스(0.0.0.0) 바인딩은 기본적으로 허용하지 않습니다. 인증서·개인키·코드·`.local` 폴더는 공유하지 마세요. 앱의 알림 등록 해제는 서버 전송 대상을 제거하며 브라우저 OS 권한은 기기 설정에서 별도로 관리합니다.
